## 2. Logic Chain

1. **Document Ingestion (Observation 1.1.1) → Empty/Garbage Chunks → RAG Grounding Failure:**
   Calling `FileReader.readAsText()` on binary formats like PDF and DOCX yields unprintable binary characters or empty strings. Because line 106 triggers a generic fallback string (`"Extracted textual concepts from..."`), neither Gemini nor the retrieval engine ever receives actual document text.

2. **Offline Fallback Engine (Observation 1.1.2) → Complete Loss of RAG Grounding:**
   When `GEMINI_API_KEY` is not present, or during rate-limit responses (HTTP 429), `generateTutorResponse` falls into its pedagogical fallback. Because this fallback ignores `ragChunks` and branches solely on `"binary search"` or `"join"`, Monday AI cannot answer grounded queries about user documents.

3. **Message Rendering (Observation 1.1.3) → Broken Typography & Escaped Markdown:**
   Rendering Gemini output via `whitespace-pre-line` directly causes headings (`###`), asterisks (`***`, `**`), bullet characters (`*`), and code fences (```` ``` ````) to be displayed raw to students, directly violating requirement R1.

4. **Lecture Materials Data Model & UI (Observations 1.2.1 & 1.2.2) → Non-Functional File Sharing:**
   Without a file upload handler in `src/app/teacher/page.tsx`, instructors cannot publish actual slides or PDFs. Because `CourseMaterial` does not store file binary/text payloads, downloads in `courses/[courseId]` default to generic mock text.

5. **Notes Studio Architecture (Observations 1.2.3 & 1.2.4) → Disconnected Student Workflow:**
   Because student notes are stored only in isolated lesson keys (`notes_${cId}_${lId}`) and not in a unified `StudentNote` store, students have no central locker on `/dashboard` and cannot toggle multi-note selections into Monday AI's RAG drawer.

6. **QuizForge Generation & Curation (Observations 1.3.1 & 1.3.2) → Mock Generation & Lack of Teacher Studio Control:**
   In `/quizzes`, `handleGenerateCustomQuiz` bypasses AI and injects 3 fixed divide-and-conquer questions. In `/teacher`, the lack of selection checkboxes, edit inputs for text/distractors, and point value fields prevents teachers from curating assessments.

7. **Data Model Leakage (Observation 1.3.3) → Cohort Analytics Contamination:**
   Because teacher grading queries filter only by `userRole !== "teacher"`, student self-practice attempts on `/quizzes` are mixed into the instructor's official course grading tables.

## 3. Caveats

1. **No Backend Database (Client-Side / LocalStorage Architecture):**
   CampusOS operates primarily as a client-side Next.js application backed by `localStorage` (`src/lib/store.ts`). Real file uploads (PDF, DOCX) must be stored in browser memory or base64/data URLs within reasonable size limits (e.g., < 10MB) to prevent `QUOTA_EXCEEDED_ERR`.
2. **Pure In-Browser Document Parsing:**
   Heavy server-side binaries (like poppler-utils or LibreOffice) are not present. In-browser PDF and DOCX parsing must rely on reliable client-side decoders (e.g., parsing PDF stream text objects and unzipping DOCX XML `<w:t>` tags).
3. **No Caveats Beyond the Above:**
   The codebase builds successfully with 0 errors (`npm run build`) and all 15 unit tests pass (`npm run test`).

## 4. Conclusion & Implementation Blueprint

To satisfy requirements R1, R2, and R3, the engineering team must implement the following architectural solutions:

### R1 Implementation Blueprint: Dynamic In-Browser RAG & Markdown
1. **In-Browser Document Parser (`src/lib/rag-parser.ts`):**
   - Implement clean client text extractors for:
     - `.pdf`: Extract text from uncompressed and deflated streams (decoding `BT...ET`, `Tj`, `TJ` operators).
     - `.docx`: Unzip and extract XML text nodes (`<w:t>`) across paragraph blocks (`<w:p>`).
     - `.csv` / `.tsv`: Robust row and column parsing into structured semantic chunks.
     - `.txt` / `.md`: Chunk with slide / section boundary awareness.
   - Enforce 10MB max file size validation with user-facing alerts.
2. **Enhanced Vector Retrieval & Cosine Similarity (`src/lib/rag-engine.ts`):**
   - Normalize TF-IDF vectors using Euclidean norm ($L_2$) to compute true cosine similarity.
   - Add phrase matching boost and fallback semantic chunking for broad document queries.
3. **High-Fidelity Grounded Local RAG Fallback (`src/lib/ai-provider.ts`):**
   - When Gemini is offline or rate-limited, synthesize responses directly from top-scoring `ragChunks` with citations (`[Source: filename, Section X]`).
4. **Markdown Rendering Component (`components/ui/MarkdownRenderer.tsx`):**
   - Convert headings (`#`, `##`, `###`), bold (`**`), italic (`*`), clean list items, and horizontal rules without raw `***` or unrendered syntax.
   - Format inline code `` `code` `` and multiline fenced code blocks with language badges and copy-to-clipboard functionality.

### R2 Implementation Blueprint: Dual-Tier Lecture Notes & Materials
1. **Data Model Updates (`src/types/index.ts`):**
   ```typescript
   export interface StudentNote {
     id: string;
     userId: string;
     title: string;

     fileSize?: string;
   ```

   - Update `CourseMaterial` to include `fileData?: string` and `fileName?: string`.
2. **Store CRUD (`src/lib/store.ts`):**
   - Add `getStudentNotes(userId)`, `saveStudentNote(note)`, `deleteStudentNote(id)`, and `deleteCourseMaterial(courseId, materialId)`.
3. **Teacher Course Materials in `/teacher` and `/courses/[courseId]`:**
   - Real file upload dropzone for lecture slides/PDFs with true file size, timestamp, and delete actions.
   - Clean download triggers returning the actual uploaded document or formatted lecture content.
4. **Student Personal Notes Studio & RAG Drawer:**
   - On `/dashboard`: Add "Personal Notes Locker" with upload, view, delete, and "Study with Monday AI" actions.
   - On `/tutor`: Add multi-file selection drawer allowing students to check/uncheck 1 or multiple notes to feed into active RAG context.

### R3 Implementation Blueprint: Dynamic QuizForge & Role Separation
1. **Data Model Updates (`src/types/index.ts`):**
   - Add `points?: number` to `Question`.
   - Add `isPractice?: boolean` to `Quiz` and `QuizAttempt`.
2. **Teacher Quiz Studio (`/teacher`):**
   - Generate dynamic questions from uploaded lecture notes via `/api/ai/quiz` (with local grounded fallback).
   - Interactive Question Curation:
     - Checkbox selection (select/unselect questions to include in final assessment).
     - Inline editing of question prompt, distractor choices, and correct answer index.
     - Configurable points per question (e.g. 5 pts, 10 pts).
3. **Student Practice QuizForge (`/quizzes`):**
   - Allow students to upload notes or paste text to generate custom quizzes dynamically via `/api/ai/quiz` (eliminating hardcoded fixtures).
   - Strict data isolation: Mark student self-practice attempts with `isPractice: true` or `creatorRole: "student"`.
   - Update `/teacher` cohort analytics to filter strictly by teacher-assigned assessments:
     `attempts.filter((a) => !a.isPractice && officialQuizIds.has(a.quizId))`.
